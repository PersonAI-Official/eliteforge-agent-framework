# 本地文件访问、编辑与搜索设计

## 目标与边界

文件工具在宿主进程内运行，所有操作受应用配置的文件根目录约束。路径必须相对 `FileSystemToolsConfig::new(root)` 指定目录。
绝对路径、`..` 和符号链接（包括悬空链接）均被拒绝。读取／搜索和写入需分别启用对应能力包。

## 文件版本与补丁

`fs_read_text` 返回内容、行数和 `sha256` 版本指纹。写入使用 `fs_write_text`；覆盖前必须完整读取当前内容。`fs_apply_patch` 的 `mode=text` 按已读取的文本精确替换，默认要求唯一匹配；`replaceAll: true` 必须同时提供准确的 `expectedCount`。

`mode=patch` 使用 `*** Begin Patch` / `*** End Patch` 包裹多文件变更，支持 Add File、Delete File、Update File。移动使用 `*** Update File: 旧路径` 后跟 `*** Move to: 新路径`；`dryRun` 只预览。原有 `fs_apply_unified_patch` 和模型提供版本参数不再使用。

写入结果包含前后版本与 diff。协调和版本检查不能替代 Git、备份或崩溃恢复日志；外部进程仍可能与文件操作竞争。文件和目录访问受宿主配置的路径授权及符号链接策略限制。

## 搜索

`search_grep`、`search_glob`、`search_path` 保留名称和原有基本参数，并支持：

- 完整 glob：`**/*.rs`、`**/*.{rs,toml}`、字符范围；`*` 不跨目录分隔符。
- `exclude` 排除匹配路径；模式相对配置的文件根目录。
- 默认遵守搜索目录内的 `.gitignore`、`.ignore` 和 `.git/info/exclude`，即使目录不是 Git 仓库。
  `respectGitIgnore: false` 关闭这些规则；不读取搜索目录外的父级规则或全局 Git ignore。
- `search_grep` 的 `fixedStrings`、`caseSensitive`、`word` 和 `contextLines`。
  `mode` 为 `content`／`files`／`count`，结果字段分别为 `matches`／`paths`／`counts`；计数单位是匹配行。
- `search_path` 用 `entryType` 选择文件或目录；符号链接不参与搜索。

`maxResults` 是每页条数，受宿主配置约束。续读重复相同查询并附带 `nextCursor`，可改变每页条数。
结果来自第一次扫描的快照：后续文件变化不会导致分页跳项，但续读内容可能已经过时。
快照绑定当前 Framework 安装实例和会话，保留 120 秒，最多 8 份；过期或被淘汰后需重新搜索。
这不是文件系统在某一时刻的原子快照。

扫描最多 5 秒、10000 个目录项、32 MiB 文件内容；单个文件默认最多 256 KiB。
保留结果最多 10000 行或 2 MiB 序列化内容，单行正文最多 8 KiB。
检查 `complete`、`limitReason`、`skipped`、`textTruncated` 和 `truncated`，不要把受限扫描当成无遗漏结果。
`nextCursor` 只续读已保留的结果，不会继续超限扫描；`complete` 描述本次根目录、深度和过滤条件内的扫描。
搜索循环检查运行取消；进程内同步文件系统调用本身不能被强制中断。

行为测试见 [capability_packs](../crates/capability/eliteforge-agent-capability-tools/tests/capability_packs.rs)
和 [编辑回滚测试](../crates/plugin/tool/eliteforge-agent-official-plugin-tools-local/src/edits.rs)。

## 宿主读取工具目录

`eliteforge_agent_official_plugin_tools_local::local_tool_catalog()` 返回本插件文件、搜索、编辑与系统命令工具的真实 `ToolDescriptor`。
目录使用与执行绑定相同的描述定义，供宿主显示、策略迁移和重复工具检查使用；不会打开文件、启动命令或安装插件。
描述不表示授权，宿主仍须显式选择对应能力包，并由执行阶段实施目录和命令策略。

宿主可用此目录检查本地公共工具是否重复定义。其他插件的工具目录由宿主按实际选择的能力另行提供。
## 每次运行的目录授权与注意事项

`ScopedLocalToolsPlugin` 在建立 run lease 和每次原生 executor 入口调用宿主的
`LocalToolScopeProvider::snapshot`，获取一次原子的 `LocalToolScopeSnapshot { revision, grant }`。
默认实现重新调用既有 `grant` 并按完整授权配置生成摘要 revision；宿主也可提供显式版本。
同一 run 中同 revision 对应不同 grant 会被拒绝，terminal owner 和已发布调用契约不能改变。
等待异步 scope 时遵循 run 的取消与 deadline。
授权包括 `FileSystemToolsConfig`、命令策略、可调用工具 ID、调用名映射和初始可见工具集合。
宿主可以更新当前执行上下文，后续工具调用会重新获取 scope；模型参数不能扩展授权根目录。
`with_authorized_roots` 支持多个根目录，绝对路径仍须落在这些目录内。
`with_authorized_symlinks(true)` 显式允许解析后仍处于授权范围内的别名。
配置的 cwd 或根目录消失时返回错误，不回退到宿主进程目录。

`FileReferenceReaderService` 让宿主解析产品附件引用，公共工具传递输入大小上限，
宿主负责会话/用户归属校验和有界读取。普通文件路径继续走公共目录检查。
补丁 envelope 支持 dry-run、统一 diff 和移动；拒绝把符号链接路径当成待删除的普通文件。
无斜杠的 glob 按 basename 在各层目录匹配，带路径的 glob 保留根目录相对语义。

每个 revision 的 executor 与搜索分页状态在 run lease 内保留，命令任务和 PTY 始终复用
插件原有的 process/service owner。持久任务和 PTY 的读取、写入、列表重新检查当前目录授权；
停止仍可清理旧资源。已启动进程不构成操作系统沙箱，撤销目录授权不回滚已完成效果。
PTY 调用的 Drop/tool timeout 会拒绝排队启动，并请求停止该次调用新建的迟到会话；
幂等重放不接管此前已接受会话的取消生命周期。若底层同步 spawn 永不返回，无法确认终止；
原生 worker 在登记会话后请求停止，Agent/服务关闭仍承担最终资源生命周期。

可信产品命令可 await `capture::capture_command_in_run` 或 `capture_command_with_cancel`，
与已有 run/取消控制结合，进程仍由原生命令 owner 管理。同步兼容入口保留，异步 run 不应
把这些命令放进无法取消的 blocking waiter。取消后的结果表示请求停止，不承诺效果回滚。

集成用例见 `eliteforge-agent-framework/tests/host_local_grants.rs`、`dynamic_local_scope.rs`、
`native_capture_control.rs`、`pty_invocation_timeout.rs`，以及本插件的 `pty_tools/cancellation_tests.rs`。

- 目录约束只作用于这些文件工具，不是操作系统沙箱；被授权命令仍由命令执行策略单独约束。
- 补丁提交使用进程内锁和回滚，不提供跨进程事务或断电恢复日志。遇到 `Indeterminate` 时应检查列出的路径，再决定后续修复。
- 搜索分页使用首次扫描保留的结果清单，不构成文件系统原子快照；应检查 `complete` 和截断字段后再据此决策。
